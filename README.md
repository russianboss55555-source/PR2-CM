# ПР № 2. Визуализатор зависимостей Cargo

Конфигурационное управление · вариант 22. Программа читает метаданные
пакетов Rust из HTTP(S)-индекса Cargo или локального тестового JSON, строит
граф рекурсивным BFS и сохраняет его в DOT и SVG. Для тестового репозитория
можно найти все пакеты, которые прямо или транзитивно зависят от выбранного.

## Подготовка и запуск

Нужны Python 3.9+ и Graphviz с командой `dot` в `PATH`. На Windows
проверьте доступность команд через `python --version` и `dot -V`.
Отдельная сборка и установка пакетов через pip не требуются.
Cargo нужен для контрольного сравнения в конце работы.

Команды для PowerShell выполняются из корня репозитория. Справку можно
открыть командой `.\run.bat --help`. На Linux и macOS используйте
`python3 src/main.py` с теми же параметрами.

## Этап 5. Демонстрация пакета itertools

Для демонстрации визуализации используйте пакет Cargo `itertools`.
Имя пакета в аргументе `--package` пишется строчными буквами.

```powershell
.\run.bat --package itertools --source https://index.crates.io --output out/itertools.svg --ascii-tree
Invoke-Item .\out\itertools.svg
```

В консоли появится дерево `itertools → either`. Изображение `out/itertools.svg`
можно открыть в браузере. Файл `out/itertools.dot` содержит описание графа.

## Параметры

| Параметр | Назначение |
| --- | --- |
| `--package` | Имя пакета Cargo. В тестовом режиме одна буква A–Z. |
| `--source` | URL HTTP(S)-индекса Cargo или путь к локальному JSON-файлу. |
| `--test-mode` | Использовать локальный JSON. По умолчанию выключен. |
| `--output` | Путь с расширением `.svg`. В обратном режиме команда возвращает список в консоль. |
| `--ascii-tree` | Напечатать ASCII-дерево при создании SVG. По умолчанию выключен. |
| `--reverse` | Найти обратные зависимости. Используется вместе с `--test-mode`. |

У булевых параметров есть формы `--no-test-mode` и `--no-ascii-tree`.
Некорректная настройка даёт код 2. Ошибка чтения репозитория, разрешения
версии или визуализации даёт код 1 и сообщение в stderr. При проверке ошибок
подставьте по очереди `--package "bad name"`, `--source invalid-url`,
`--test-mode=maybe`, `--output graph.png` и `--ascii-tree=maybe`.

## Этапы

| Этап | Реализация |
| --- | --- |
| 1 | Валидация пяти настроек и вывод `ключ=значение` в прототипе. |
| 2 | HTTP-запрос к индексу и вывод всех прямых деклараций выбранного выпуска. |
| 3 | Рекурсивный BFS по слоям, тестовый JSON, общие вершины и циклы. |
| 4 | Разворот всех рёбер тестового репозитория и повторный запуск BFS. |
| 5 | Сохранение DOT и SVG, ASCII-дерево по флагу и сравнение с Cargo. |

Пять основных коммитов этапов можно показать командой
`git log -5 --oneline e1cb06d`. Для этапа 4 в итоговой версии доступен
`--reverse`.

### Прямые и транзитивные зависимости

Индекс хранит JSON-запись на каждый опубликованный выпуск. Адрес строится
по имени пакета. Выбирается новейший стабильный выпуск без отметки `yanked`.
Если стабильных выпусков нет, выбирается новейший предварительный выпуск.
На этапе 2 в консоль выводятся все декларации, в том числе `dev` и `optional`.

В итоговом графе учитываются зависимости `normal` и `build`, а также
опциональные связи, активированные собственной группой `default` соответствующего
выпуска. Для ребра выбирается новейшая допустимая версия по требованию Cargo.
Сеть используется для чтения метаданных. В тестовом режиме входной объект
содержит ключи-пакеты и списки их прямых зависимостей.

```json
{"A": ["B", "C"], "B": ["D"], "C": ["D"], "D": ["A"], "E": []}
```

Команды для локального тестового графа и запуска автотестов в PowerShell.

```powershell
.\run.bat --package A --source tests/fixtures/cycle.json --test-mode --output out/cycle.svg --ascii-tree
.\run.bat --package D --source tests/fixtures/diamond.json --test-mode --output out/reverse.svg --reverse
python -m unittest discover -s tests -v
```

На Linux и macOS для запуска автотестов используйте `python3`.

На этом графе BFS посещает вершины в порядке `A, B, C, D`. Ребро `D → A`
сохраняется, хотя `A` уже посещён. ASCII-дерево помечает обратное ребро как
`[cycle]`, а повторно встреченную общую вершину — как `[shared]`.
При запросе `--reverse` для `A` на такой схеме результатом будет
`A <- D, B, C`. Вершина `E` изолирована. В `diamond.json` запрос для `D`
даёт `D <- B, C, A, E`, для `F` — `F <- (none)`.

### Структура программы

| Модуль | Ответственность |

| `src/cli.py`, `src/main.py` | Параметры, валидация, выбор источника и режима, обработка ошибок. |
| `src/registry.py` | Пути индекса, загрузка JSON-строк и кэш выпусков. |

| `tests/`, `demo/compare_cargo.py` | CLI-тесты, тестовый HTTP-индекс и сравнение со штатным Cargo. |

## Три примера и сравнение с Cargo

```powershell
cargo --version
python demo/compare_cargo.py
```

Скрипт вызывает визуализатор для `itertools`, `either` и `aho-corasick`,
сохраняет их DOT и SVG в `out/` и печатает дерево для каждого. Затем он создаёт
временный Rust-проект с одним пакетом той же версии и запускает
`cargo tree --prefix depth --no-dedupe --edges normal,build --target all`.
Сравниваются множества пар «имя + версия» и направленных рёбер. Строка
`MATCH` означает полное совпадение, при расхождении выводятся отличия.

Возможные причины расхождений на других пакетах включают объединение
features из разных входящих рёбер, ограничения версии Rust, конфликты версий
и фиксированные версии из Cargo.lock. Визуализатор читает один реестр,
учитывает все целевые платформы и подбирает каждую версию отдельно.
Cargo разрешает версии и features на уровне целого проекта.
